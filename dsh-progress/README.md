# dsh-progress

让模型干活时**主动报进度**，并且在方向跑偏时**提醒或拉回**。

不报就提醒；还报，就把它拦下来。方向偏了不会硬拦，只会在对话尾部放一条核对/纠偏，或者在回合结束前把它拉回一步。

0.3.0 起把原来的 `dsh-running-sessions` 并了进来：同一个插件在侧栏和标题栏汇总**跨工作区的运行中 / 等待你处理 / 刚完成会话**，列表每一行直接显示该会话最新一条进展。入口开关就放在插件自己的界面里，不再出现在设置面板。

## 它解决什么

模型执行多步任务时，工具调用、读文件、跑命令都不会出现在对话里——用户只看到输入框上面一直转圈，不知道它在干什么、卡在哪、为什么改了方向。这个插件做三件事：

1. **逼它汇报**：把“汇报进展”变成必须调用的工具，连续不汇报先软提醒，超过硬上限就拦下一次工具调用。
2. **发现方向偏了**：用目标、路径、工具调用这些硬事实做规则判断，在跑偏时给一条上下文提醒，严重时用 `agent.steer` 把它拉回一步。
3. **少走工具弯路**：bash 里用 `cat/grep/find` 这类简单命令、报了完成却没验证时，给一条即时工具提示。

全程**不调用任何模型**，不增加 token 请求，也不改系统提示。

## 用户看到什么

1. **对话里的进展卡片**：每次 `report_progress` 留一张卡片——开始 / 进行中 / 遇到问题 / 卡住了 / 已完成，五种状态，带一句话摘要、细节和下一步。
2. **输入框上方的状态条**：会话运行中显示最新一条进展（`进行中 · 正在跑测试` + 下一步），宽度与输入框一致并居中；汇报 `done` 或会话空闲时自动消失。本会话空闲时，如果别的会话还在跑或等你确认，这里改成一句「其他会话 1 个运行中 · 1 个等你确认」，点不打扰当前对话。
3. **标题栏计数片**：`1运行中 1待确认`，点开是本标签页里三条分组列表——「待我处理」「运行中」「刚完成」，按时间窗口过滤。页脚可以切换 15/30/60/120 分钟窗口。
4. **侧栏「进行中」整页列表**：和计数片同一套数据，空间更大，适合同时开很多会话时看全局。
5. **每行显示最新进展**：列表的副标题优先显示该会话在本标签页见过的最新一条进展（如 `dsh-0.2.1-rc.2 · 正在校对 README`）；没有进展时退回「等待确认 / 正在执行 / 已完成」。
6. **入口开关在插件里**：「入口显示」折叠区（标题栏弹层和整页列表各一处）可以关掉侧栏入口或标题栏计数片；为保证随时找得回来，两个入口至少保留一个，最后一个开关会锁住。开关只记在这台浏览器里，不会发消息、不进设置面板。
7. **三种上下文行**（不是弹窗，也不打断工具）：
   - `方向核对`：把“用户要什么、你最近在做什么、哪里可疑”摆出来，让模型自己停一下。
   - `方向纠偏`：更严重时发一条 steer，模型下一步会先处理方向问题。
   - `工具提示`：bash 里绕远路、报完成没验证时的一条建议。
8. **纯状态消息不打扰**：像“已经重启了web”“好了”“收到”“测试通过了”这类短确认，不会触发方向核对、方向纠偏或工具提示。动作请求（“重启服务”）和负面状态（“还是不行”）仍按正常任务处理。

## 会话总览（0.3.0 合并）

- 数据只来自这三个只读来源：`ctx.sessions.list`（会话标题/运行状态/cwd）、`ctx.uiSession.sessionStatus`（等你确认）、`ctx.workspaces.list`（工作区与归档）。插件不会创建、关闭或切换你的会话。
- 过滤规则：空会话、子 agent、已归档会话不出现；正在等确认的归「待我处理」，其余运行中的归「运行中」，窗口内刚结束的归「刚完成」；同一会话只出现一次，等你确认优先于运行中。
- 点击一行通过 `ctx.uiWorkspace.openSession` 打开对应工作区里的会话。
- 进展副标题是本标签页内的纯 UI 记忆，不写盘、不发给模型；刷新页面后等待新的 `report_progress` 重新填充。
- 两个入口的开关键名是 `dsh-progress.entry.nav` / `dsh-progress.entry.chip`，窗口键是 `dsh-progress.window`；首次读取会回退到旧的 `dsh-running-sessions.*`，所以从旧插件升级不会丢选择。

## 双模式：清晰目标严一点，模糊目标先对齐

| 模式 | 怎么判断 | 怎么管 |
| --- | --- | --- |
| 清晰 | 用户给了文件路径、命令、报错/状态码 | 查只读不写、改出范围、完成未验证、目标没完成 |
| 模糊 | 没有路径/命令/报错，或出现“优化/好看/帮我弄/随便/研究一下”等 | 先让模型用一句话对齐目标；之后只按它自己写下的 goal/todo 对照，不惩罚探索 |

拿不准按模糊处理；新用户消息变具体时自动切清晰并重置预算。

## 模型怎么被管住

### 进展门禁（原有能力）

| 情况 | 结果 |
| --- | --- |
| 连续 7 次工具调用没汇报 | 对话尾部插入一行 `进度提醒`，不打断工作 |
| 连续 10 次没汇报 | **下一次工具调用被拒绝**，理由要求先调 `report_progress`；调完立刻恢复 |
| 工具需要你审批（`ask`） | 同样先看预算：超了就先要求汇报 |
| 连续 3 次工具调用失败且没汇报 | 同样拦下，理由要求说明问题出在哪 |

### 方向与工具教练（0.2.0 新增）

| 情况 | 结果 |
| --- | --- |
| 模糊目标、还没有 goal/todo | 第一次工具调用追加一次 `方向核对`，请它先写清“要什么、第一步、怎么算完成” |
| 清晰 + 要改动 + 连续 8 次没成功写入 | 第一次汇报 `方向核对`；第二次仍只读，`方向纠偏` 拉回 |
| 清晰 + 用户点名路径，写入越界 | 第一次 `方向核对`；第二次 `方向纠偏` 拉回 |
| 报 `done` 但上次写文件后没成功测试/构建 | `工具提示`；收工时仍未验证，`方向纠偏` 拉回 |
| 收工时 goal 仍 active / 自己写过计划却没报 done/blocked | `方向纠偏` 拉回一次 |
| 收工时没有计划、也没报 done/blocked，且已调工具 >=3 次 | 一次轻量 `方向核对`（不是硬拉） |
| bash 里简单 `cat/grep/find/ls`，且没有管道/重定向 | `工具提示`，建议用 `read/grep/glob` |
| 纯状态/确认消息（“已经重启了web”“好了”“收到”“测试通过了”） | **不提醒**：跳过方向核对/纠偏和工具提示；动作请求、负面状态、问句仍按原流程 |
| 同一工具+参数原样重复失败 | **不重复提醒**，交给基座 `dsh-repeat-tool-reminder` |

共同边界：方向类只提醒/steer，**绝不 deny**；跳过 PTC 内层、子 agent、`ask_user_question`、plan mode；报 `blocked` 后停止方向判断；每回合最多 2 次拉回、3 条工具提示；新用户消息重置预算。纯状态消息只跳过方向/教练提醒，“连续不汇报”的进度提醒仍然保留。

## 配置

`cordis.patch.yml` 里的 `config`（改完重启 DSH 生效）：

```yaml
- insert:
    - id: dsh-progress
      name: dsh-progress
      config:
        softLimit: 7            # 连续多少次没汇报时提醒一次
        hardLimit: 10           # 连续多少次没汇报后拦下一次工具调用
        failuresBeforeBlock: 3  # 连续多少次失败未汇报也拦
        subagents: false        # 子 agent 是否也管（默认不管，避免刷屏）
        exempt: ['ask_user_question']  # 不计数、不拦的工具
        enforce: true           # false = 只提供工具，不提醒、不纠偏、不拦截
        enabled: true           # false = 插件完全不生效
        direction: true         # 偏离目标时提醒/拉回
        coach: true             # 工具使用提示
        maxCorrections: 2       # 每回合最多拉回几次（0 = 只核对）
        noWriteLimit: 8         # 清晰目标连续多少次没写入时开始核对
```

配置项未知、类型不对、`noWriteLimit < 3`、`maxCorrections < 0` 都会直接报错，不会静默跑错。

浏览器端的「入口显示」和 15/30/60/120 分钟窗口**不属于**上面的行为配置，只存在当前浏览器的 localStorage，刷新/重启都不会发给宿主，也不会出现在设置面板。

## 已知边界

- **不调用模型**：没有 AI 评审，规则看不懂“语义上的跑偏”；它只能抓硬事实（路径、写入、验证、goal、计划）。
- **不保证模型服从**：`agent.steer` 只是把消息放到下一步，模型仍可能继续自己的做法。
- **不自动回滚**：不会撤销文件、不会改 goal/todo；拉回只给建议。
- **方向类不拦截**：唯一硬拦截仍是“不汇报就拦”，不会因为怀疑跑偏而拒绝工具。
- **纯状态识别偏保守**：只认“已经发生的结果”和短确认；拿不准时按正常任务处理，宁可多问一句，也不漏掉真正的工作。
- **进度提醒不受纯状态规则影响**：如果模型在状态消息后开始多步工作，连续不汇报仍会被提醒/拦截。
- **重复失败/重复调用**：交给基座 `dsh-repeat-tool-reminder`，本插件不重复。
- **plan mode 不判断方向**：计划阶段本来就在探索，避免误伤。
- **子 agent 默认不管**（`subagents: true` 可打开）：子 agent 的提醒会刷屏主对话。
- **PTC（`run_code` 内层）不判断**：模型卡在代码里，中途插消息没有意义。
- 一次汇报最多记 240 字摘要 / 1200 字细节，超出截断。
- 回合开始时计数清零，回合结束或会话关闭时释放状态。
- 会话总览是**本标签页的只读视图**：不会后台轮询、不推送通知、不跨浏览器同步；入口开关和窗口选择只存在这台浏览器。需要“任务完成/等待确认”的系统通知，仍由 `dsh-mobile` 负责。
- 列表里的「最新进展」是内存里的 UI 记忆，刷新页面后从空开始；没有新汇报时会退回状态短语。
- 两个入口至少保留一个（最后一个开关会锁住），所以不存在“把两个入口都关掉、再也找不到设置”的状态。

## 变更记录

### 0.3.0（2026-11-07）

- 合并 `dsh-running-sessions`：新增标题栏计数片、侧栏「进行中」整页列表、跨工作区会话分组（待我处理 / 运行中 / 刚完成）。
- 输入框状态条在本会话空闲时改为提示其他会话的活动，不再只是一片空白。
- 会话列表每行显示该会话在本标签页见过的最新进展；没有进展时退回「等待确认 / 正在执行 / 已完成」。

- 测试 55 条（客户端合并卡片、活动条、计数片、整页列表、入口开关与旧回归）。

### 0.2.1（2026-11-06）

### 0.1.1（2026-11-06）

- 提醒在对话里显示为中文 `进度提醒` 标签，并带上原因（如 `7 次调用没汇报，其中 1 次失败`）。

- 长对话里滑出历史窗口的旧汇报不再被误标成「汇报失败」。
- 会话关闭时立即释放该会话的计数。
