# dsh-compact-memory 方案：压缩后不丢工作经验

> 目标：让 dsh 的长会话在被压缩后，仍然记得“为什么这么做、试过什么、下一步是什么”。
> 结论先行：**插件默认辅助原生压缩，不替代它；默认触发点与原生相同（本机 57.13%），绝不更早。**

---

## 0. 一句话

dsh 的 `compaction-basic` 负责“怎么压”（token 计量、工具配对边界、日志锁、失败重试、KV-cache 复用）；本插件负责“压前保存、压后接上”：把工作现场写成交接卡，压缩成功后自动放回对话，并保留原始日志的回查入口。

---

## 1. 先回答三个关键问题

### 1.1 上下文大于多少百分比才触发？会不会过早？

这台机器（`magpie / ollama-cloud/deepseek-v4.1-flash:1017`）的实际参数：

- `W`（窗口）= 1,048,576
- `O`（输出预留，模型的 `maxTokens`）= 384,000
- `B`（compaction headroom）= 65,536

dsh 原生公式（源码 `resolveCompactSpec`）：

```text
native = floor(min(W × 0.8, W − O − B))
       = floor(min(838,860.8, 599,040))
       = 599,040 tokens
       = 57.13% of W
```

所以 **80% 只是公式里的名义上限，本机真正的触发点是 57.13%**。这不是插件提前，是 dsh 先把 384K 输出和 64K headroom 扣掉了；1M 窗口里只有 599K 可用于输入。

| 模式 | 触发点 | 占 1M 窗口 | 说明 |
|---|---|---|---|
| **`boundary`（默认）** | **599,040** | **57.13%** | 与原生同阈值，只在回合结束、agent 空闲时执行；**绝不更早** |
| 早期草案 `0.95×原生` | 569,088 | 54.27% | 比原生早约 30K；已改为非默认 |
| `early` + `0.9×原生` | 539,136 | 51.42% | 显式选择才启用 |
| `window` + `0.5W` | 524,288 | 50.00% | 显式选择才启用 |
| `window` + `0.7W` | 599,040 | 57.13% | 高于原生阈值会被截断，**不会更晚** |
| `native` | 599,040 | 57.13% | 插件不调 `/compact`，只做记忆卡 |

硬保证：

```text
boundary: trigger = native
early:    trigger = floor(native × clamp(triggerAtNativeRatio, 0, 1))
window:   trigger = floor(min(W × atWindowRatio, native))
```

任何模式下 `trigger <= native`，测试会断言。

**会不会过早？默认不会。** 只有显式选 `early`/`window` 才会更早。每次压缩都是有损的；越早压，压缩次数越多，复利损失越大（见 1.2 的 Compaction Cliff）。默认把压缩放在回合边界，而不是一步中间。

**能不能更晚？插件不能。** 原生会在 57.13% 自己压；要更晚只能改 dsh 的 `maxTokens` 或 headroom。如果实际不需要 384K 输出，把 `maxTokens` 调到 64K，原生阈值会变成约 80%——这是 dsh 模型配置的取舍，不是本插件能改的。

### 1.2 压缩前把工作经验写入文档，有没有用？

**只写文档：作用有限。** 原因：

1. 模型不一定会再读；工具存在 ≠ 会被调用。
2. 摘要器不会自动把这份文档纳入摘要输入。
3. 文档可能过期；压缩时它可能已经不是最新状态。
4. 如果文档写在会被压缩的对话里，它自己也会被 shadow 掉。
5. 只写“事实”，不写“为什么/试过什么”，仍然会丢程序性经验。

**写成闭环：作用很大。** 六个必要条件：

1. **在 shadow 之前写**：连续在回合边界写，或在 `compaction/start` 时冻结快照。
2. **结构化**：目标 / 决定及原因 / 约束 / 坑 / 进度 / 下一步 / 关键文件与目录。
3. **有界**：默认 ≤ 6000 字符；按优先级裁剪。
4. **自动回注**：压缩成功后的下一个 `agent/pre-step` 把卡片作为一条消息放回对话。
5. **可回查**：卡片里给出去原始日志/完整卡片的路径与工具。
6. **增量更新**：每次只改相关小节，不整篇重写。

证据：

- **Compaction Cliff**（arXiv:2608.22752）：20 个生产 agent 配置上，Claude Code 的 `/compact` 一轮后安全规则只剩 **53%**，五轮后 **10%**。这说明“写进摘要”本身并不保证经验存活。
- **ACE**（arXiv:2510.04618）：摘要式压缩有 brevity bias 与 context collapse；结构化、增量更新能保住细节。
- **billion-context**：外部事实库能存“是什么”，但会丢程序性上下文（为什么这个修复生效、哪条路失败过）。
- **Claude Code**：压缩后会自动重载 `CLAUDE.md`、memory、skills、最近修改的文件；它不是“只写文档”，而是“写完还会自动放回来”。
- **Anthropic memory tool**：`/memories` 文件 + 工具读写，证明“文件即记忆”可行；但需要应用侧 handler，且不会自动回注。
- **Letta**：memory blocks 常驻上下文，证明“核心记忆”有效；代价是每轮都占 token，所以本方案只在压缩后注入一次。

## 2. dsh 现状（已核验）

### 2.1 压缩在哪里、怎么触发

- `dsh-base` 挂载 `compaction-basic`、`command-compact`、`tool-result-pruner`；`dsh-web-app` 把宿主平面的 `compaction-basic`/`command-compact` 设为 `disabled: true`，改为**每个 agent preset 的 `cordis:group` 里各挂一份**。当前 web profile 的 `--dump-config` 中有 5 处 `id: compaction-basic`（1 处禁用 + 4 个 preset 子树）。
- 自动触发点：`agent/pre-step`（压力）、`agent/request`（模型切换）、`agent/request-error`（溢出恢复）。
- 阈值：`floor(min(W × 0.8, W − O − B))`；保留尾部：`0.16 × (W − O)`。
- 压缩协议：`compaction/start`（日志锁）→ `compaction/summary`（摘要、被压范围、shadowed tokens）→ 紧邻一条 `user/message`（`surfaceOp: replace`，唯一的面变更）→ `compaction/end`。原始事件仍在日志，回放可重建；`compaction/*` 全是 log-only。
- 唯一的压缩相关 Cordis 瀑布是 `compaction/summary-error`；**没有“压缩前”事件**。所以插件只能在 `session/event` 上观察 `compaction/start`，在 `compaction/end` 后行动。

### 2.2 外部插件的技术边界（已实测）

- profile 的 `node_modules` 里没有 `@deepseek-ai/dsh-session` 等核心包；从插件目录和 profile `import` 都报 `ERR_MODULE_NOT_FOUND`。
- 自己装一份会得到另一个模块副本；`appendPluginRecord` 依赖同一份 `Session` 类的私有方法 `#appendRecord`，跨副本会失效。因此**不能**用 `plugin:` 会话记录存卡片。
- 先例 `dsh-progress` 证明：外部插件可以只用 `ctx` 服务 + `node:*`，并手写 `ToolDefinition`（`name/description/parameters(JSON Schema)/output.schema/render/execute`）注册工具；`execute(args, exec)` 能拿到 `exec.agent.session.id`。
- `agent/pre-step` 是瀑布，先 `await next()` 再返回 `{...decision, messages: [...decision.messages, msg]}` 是官方先例（`dsh-plan-mode` 的 narration）。
- `session/event` 未打 scope 标签的监听器是全局的；`agent/created`/`agent/disposed` 可维护 session→agent 映射。
- `ctx.tokenMeter.contextPressure(session)` 返回 `projectedTokens`（下一次请求的预估压力，压缩后会立刻反映）与 `contextWindow`；`ctx.agents.turnBoundaryOf(session).lastTurn` 可取轮次；`ctx.commands.execute(agent, '/compact', [], signal)` 可程序化触发与 `/compact` 完全相同的路径。

### 2.3 设计结论

**不重造压缩器，做“压缩前记忆 + 压缩后接力 + 边界调度”的旁路层。** 这样风险最小，也复用 dsh 已经做对的平衡切边、锁、回放、KV-cache 复用。

## 3. 设计

### 3.1 分工：辅助原生，不是替代

| 能力 | dsh `compaction-basic` | 本插件 |
|---|---|---|
| token 计量 / 阈值 | ✅ | 只读，用同一公式算触发点 |
| 工具配对边界 / 日志锁 / 重试 | ✅ | 不碰 |
| 摘要内容 | ✅（通用摘要） | 不碰；补“经验层” |
| 压缩前保存 | ❌ | ✅ 交接卡 + 快照 |
| 压缩后回注 | ❌（只保留摘要） | ✅ 下一个 step 自动注入 |
| 时机选择 | 每步开始前 / 模型切换 / 溢出 | 可选：回合结束、与原生同阈值 |
| 原始日志回查 | ✅（事件还在） | ✅ 在卡片里给入口 |

**为什么不做成“接管压缩”**：原生已经把“压”的机械部分做对了；替换它要重做计量、锁、配对、回放，升级易碎，而且不解决真正难点——压缩后不丢经验。真正值得接管的是“摘要内容”，那可以作为第二阶段：只重写 `summarize()`，产出结构化交接摘要，但仍挂在原生引擎上。

### 3.2 三条链路 + 一条兜底

1. **写入**：模型 `worklog_write`（高质量、但不保证每次都用） + 插件事实快照（确定性的地板）。
2. **冻结**：`compaction/start` 时若卡片过期，立即从当前 surface 生成快照并落盘；此后压缩怎么 shadow 都动不了它。
3. **回注**：`compaction/end` 成功后标记 pending；下一个 `agent/pre-step` 在 `await next()` 之后把卡片追加进 `decision.messages`，只注入一次。
4. **兜底**：原始事件仍在 session log，`session_query`/`session_search` 可查；卡片里明确写出这个入口。

### 3.3 数据流

```text
turn/end ──┬─> 卡片过期? ──> buildSnapshot(session) ──> store(card.json/md)
           └─> 调度器: 压力 ≥ trigger 且 空闲
                         └─> commands.execute(agent, "/compact")

compaction/start ──> 若卡片过期: 冻结快照（source=snapshot）
compaction/summary ──> 记录 shadowedTokens / compactionId
compaction/end(ok) ──> pendingInjection = {compactionId, at}
compaction/end(err) ─> 只记日志，不注入

agent/pre-step ──> await next()
                    ├─ 有 pendingInjection 且 decision=enter ─> append 卡片消息，标记 injected
                    └─ 否则若有软提醒 ─> append 一句提醒，标记 nudged
```

### 3.4 卡片格式

`card.json`（规范源）：

```json
{
  "version": 1,
  "sessionId": "…",
  "createdAt": 1730000000000,
  "updatedAt": 1730000000000,
  "updatedTurn": 12,
  "updatedSeq": 345,
  "source": "model | snapshot | inherited | merged",
  "sections": {
    "goal": "…",
    "done": ["…"],
    "decisions": ["…（为什么）"],
    "constraints": ["必须/不要/只能…"],
    "pitfalls": ["试过但失败的…"],
    "files": ["path 或命令"],
    "next": ["…"],
    "questions": ["待确认…"]
  },
  "freeform": "模型补充的自由文本",
  "lastCompaction": { "id": "…", "endSeq": 350, "at": 1730000000000, "shadowedTokens": 480000 },
  "injected": { "compactionId": "…", "at": 1730000000000, "turn": 13 },
  "nudgedAtTurn": 12,
  "pendingNudge": null,
  "requested": { "turn": 12, "reason": "阶段完成" },
  "lastAttempt": null,
  "stats": { "modelWrites": 3, "snapshots": 1, "injections": 1, "compactions": 1 }
}
```

`card.md`：同一内容的 Markdown 版本，供人直接打开；`history/card-YYYYMMDD-HHMMSS.md` 保留最近 10 份。

裁剪优先级：`goal > next > decisions > constraints > pitfalls > done > files > questions > freeform`；每条截断 240 字符、每节最多 8 条；超限时从低优先级开始删，并在末尾加 `…（已截断）`。

脱敏：对 `sk-…`、`Bearer …`、`*_KEY=…`、私钥块做替换；不误伤 git commit hash。

### 3.5 存储

```text
$DSH_HOME/compact-memory/
  <safeSessionId>/
    card.json
    card.md
    history/
      card-20261111-101500.md
```

- `safeSessionId`：保留 `[A-Za-z0-9._-]`，其他替换为 `_`；若发生替换，追加 8 位哈希防碰撞。
- 目录 0700，文件 0600；临时文件 + `rename` 原子写。
- 读取损坏：把坏文件改名为 `.corrupt-<ts>`，从 session 事件重建快照，记 warn。
- 磁盘不可写：内存态继续工作，只 warn 一次；不阻塞对话。
- fork：`agent/created` 时若新 session 没有卡，且 `session.header.parentSession` 有卡，复制一份，`source: "inherited"`。

### 3.6 事件与状态机

监听：

- `agent/created`：建立 session→agent 映射；加载卡；`source === 'compact'` 时刷新；fork 继承。
- `agent/disposed` / `session/disposed`：清理内存映射。
- `session/event`：
  - `turn/end`：标记软提醒；调度 `maybeCompact`。
  - `compaction/start`：若卡片过期且 `snapshotOnCompactionStart`，冻结快照并落盘。
  - `compaction/summary`：记录 `shadowedTokens`、`compactionId`。
  - `compaction/end`：无 `error` → `lastCompaction` 更新、`injected=null`、测量压缩后 surface、落盘；有 `error` → 只记日志。
  - `user/message` / `assistant/message` / `tool/result`：维护最近 80 条事件的环形缓冲。
- `agent/pre-step`：`await next()`；仅当 `decision.kind === 'enter'` 且未 abort 时，注入 pending 卡片或软提醒。

状态机：

```text
idle ──compaction/start──> started ──compaction/summary──> summarized
  ^                                                         │
  │                                                         ├─end(ok)──> pendingInject
  │                                                         └─end(err)─> idle (log)
pendingInject ──pre-step(enter)──> injected ──> idle
```

幂等：

- `injected.compactionId` 已记录则不再注入。
- 插件重启后，从 `lastCompaction.endSeq + 1` 起扫描日志，若已存在带 `【工作交接卡·自动】` 标记的 `user/message`，补记 `injected`，不重复注入。
- 软提醒用 `nudgedAtTurn` 去重。

为什么 `await next()` 在注入之前：压缩可能注册在我们外层或内层。无论哪种顺序，`next()` 返回时压缩已经完成；这样同一 step 就能把卡片接在摘要后面，不必等下一轮。

### 3.7 注入消息

```text
【工作交接卡·自动】
上一段历史已被压缩成摘要。下面是压缩前保存的工作现场，请把它当作当前任务的连续上下文继续工作。

<card.md 的渲染内容>

（需要更早的原始细节：调用 worklog_read 读完整卡片；或用 session_query 检索原始会话。）
```

- 形状：`{ id: randomUUID(), role: 'user', content: [{type:'text', text}], source: { kind: 'compact-memory', form: 'notice', summary: 'Compaction handoff card' } }`，深冻结后放入 `decision.messages`。
- `summary` 截断到 120 字符。
- 若运行时对自定义 `source.kind` 不友好，配置 `sourceKind: 'user'` 回退；默认自定义，UI 对未知 kind 会走“不透明内容”的兜底。
- 软提醒更短：`【上下文提醒·自动】上下文已用约 X%。如果刚完成一个阶段，建议调用 worklog_write 更新交接卡…`

### 3.8 工具与命令

| 工具 | 参数 | 行为 |
|---|---|---|
| `worklog_read` | `{ section? }` | 返回完整卡片或指定小节 |
| `worklog_write` | `{ goal?, done?, decisions?, constraints?, pitfalls?, files?, next?, questions?, freeform?, mode? }` | 合并/替换指定小节，落盘，返回卡片 |
| `compact_request` | `{ reason }` | 记录“下个安全回合边界压缩”的请求 |
| `compact_status` | `{}` | 返回 W/O/B、原生阈值、触发点、压力、上次压缩 |

`/handoff`：查看/刷新卡片；`/handoff refresh` 强制从事件重建。

### 3.9 调度器

每轮 `turn/end` 后异步执行（不阻塞回合）：

```text
W = contextPressure(session).contextWindow
O = session.requestHeader()?.config.maxTokens ?? agent.options.maxTokens ?? 0
B = config.autoCompact.nativeHeadroomTokens
native = floor(min(W * 0.8, W - O - B))

native:   no scheduler
boundary: trigger = native
early:    trigger = floor(native * clamp(triggerAtNativeRatio, 0, 1))
window:   trigger = floor(min(W * atWindowRatio, native))
```

条件全部满足才调用：

1. `enabled` 且 `mode !== 'native'`；
2. agent 存在且未 disposed；
3. `skipSubagents` 时 `session.header.origin !== 'subagent'`；
4. `await waitIdle(agent, 2000ms)` 后 `agent.status === 'idle'`；
5. 压力（`projectedTokens ?? pressureTokens`）≥ `trigger`，或 `requested` 存在（模型请求可绕过压力门，但不绕过 6/7）；
6. 距上次压缩 ≥ `minTurnsSinceLast`；
7. 当前 `surfaceTokens - lastSurfaceTokens >= minNewSurfaceTokens`；
8. 卡片存在且未过期，否则先生成快照；
9. 全局并发 ≤ 1，每会话一个在飞任务。

调用：`ctx.commands.execute(agent, '/compact', [], controller.signal)`，超时 `timeoutMs`。结果 `kind === 'success'` 记 info；`busy/cancelled/changed` 记 debug；命令不存在（返回 `undefined`）则**一次性禁用调度器**并 warn，卡片功能继续。

### 3.10 事实快照

输入：会话事件（首见时 `session.snapshotEvents()` 全量扫一次，之后靠 `session/event` 环形缓冲；这是公开 API，虽标注 deprecated，但外部插件没有 projection 的类型/包可用）。

提取：

- `goal`：第一条 `user/message` 的文本 + 最近一条用户要求。
- `done`：`todo/write` 里 `completed` 的条目；最近 2 条 `assistant/message` 的结论行。
- `next`：`todo/write` 里 `in_progress`/`pending`；最近 assistant 文本里“下一步/接下来”开头的行。
- `decisions`：模型卡已有则保留；否则从 assistant 文本里抓“决定/选择/改为/因为/所以”等标记行，最多 5 条。
- `constraints`：从用户文本里抓“必须/不要/只能/务必/统一/禁止/不能/要求/约定”，最多 5 条。
- `pitfalls`：最近 3 条 `isError` 的 `tool/result` 文本首行 + 最近 assistant 里“失败/报错/坑/不行/回滚/踩”的行。
- `files`：最近工具调用参数里的 `file_path`/`path`/`notebook_path`/`target_file`/`command`，去重，最多 8 条。
- `questions`：模型卡已有则保留；否则空。

规则：模型卡的非空小节**永远优先**；快照只填空/过期小节；合并后 `source: "merged"`；全部脱敏、截断、去重。

### 3.11 失败模式

| 失败 | 检测 | 处理 | 用户看到 |
|---|---|---|---|
| 压缩失败/取消 | `compaction/end.error` | 不注入；记 warn | 无变化 |
| `/compact` 命令不可用 | `execute` 返回 undefined | 禁用调度器一次，warn | 原生压缩仍工作 |
| 插件重启后重复注入 | 扫 `lastCompaction.endSeq+1` 后的卡片标记 | 补记 injected，不重复 | 无重复卡片 |
| 卡片文件损坏 | JSON.parse 失败 | 备份 `.corrupt-*`，快照重建 | 卡片可能少细节 |
| 磁盘只读/满 | 写失败 | 内存态继续，warn 一次 | 对话不受影响 |
| 卡片过大 | 超 `maxCardChars` | 按优先级裁剪 | 低优先级内容被截 |
| 并发压缩 | 会话/全局在飞集合 | 直接跳过本次 | 无 |
| 会话被销毁 | `session/disposed` | 取消定时器，清理映射 | 无 |
| 子会话 | `origin === 'subagent'` | 不自动压 | 子会话仍可手动 `/compact` |
| billion-context 启用 | `/compact` 不可用/无 compaction 事件 | README 要求 `mode: 'native'` | 由其接管压缩 |
| 密钥误入卡片 | 脱敏规则 | 替换为 `[redacted]` | 无 |

## 5. 限制与风险

1. `ctx.commands.execute(agent, '/compact', …)` 从宿主层调用是否命中 agent 作用域的命令，是**唯一需要真机确认**的点；失败则调度器自动禁用，原生压缩不受影响，卡片链路照常。
2. 注入消息的自定义 `source.kind` 若被某层校验拒绝，回退 `{ kind: 'user' }`（配置开关）。
3. 原生阈值公式若被部署改过（`headroom`/`thresholdRatio`），插件的触发点会偏；`compact_status` 打印实际值。
4. `session.snapshotEvents()` 标注 deprecated；只用于首见/重建，不用于热路径；未来若移除，改用 `ctx.sessionQuery` 读取。
5. 卡片是外部文件，不随 session log 复制；fork 只在创建时继承一次。若手动删目录，会退化为“无卡”，压缩仍工作。
6. 没有“零丢失”保证；原始日志是最终兜底，卡片只是把关键经验前置。
7. **本插件不能让原生压缩变晚**；要变晚只能改 dsh 的 `maxTokens`/headroom 配置。

假设：

- dsh 0.2.2-rc.1（当前安装版）的 API 如本方案所读；升级后需复查。
- Web profile 的 per-agent `/compact` 保持启用（已核验 5 处挂载）。
- 未打 scope 标签的宿主监听器能收到所有 agent 的 `session/event`/`agent/pre-step`（`dsh-scope` README 明确“Untagged listeners stay global”）。
- `$DSH_HOME` 可写；卡片不含用户不希望的敏感信息（已做基础脱敏）。
- 本轮不安装、不重启；Phase B 需要单独确认。

## 6. 后续：如果真要“接管摘要”

当前是“辅助原生”。如果以后想让摘要本身带结构化交接，可以做第二阶段：

- 继承 `BasicCompactionEngine`，只重写 `summarize()`，保留原生的计量、锁、配对、重试。
- 在摘要 prompt 里要求输出固定的“工作交接”小节（目标/决定/约束/坑/下一步/文件），或做一次单调用双产出。
- 需要把 `compaction-basic` 在每个 agent preset 的挂载替换成新实现；升级 dsh 时要复查 preset 结构。
- 风险：比“旁路层”高；收益是摘要质量更任务感知。

在 Phase B 真机验证通过、且确认现有卡片链路稳定之前，不建议做这一步。
